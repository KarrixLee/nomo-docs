五条命令，每个智能体上都是同样的五条。你要在想影响的那台电脑上、从一个智能体会话里运行它们——在 Claude Code 和 OpenCode 里是 `/` 命令，在 Codex 里是 `$` skill。

<Tip>
  Claude Code 里一切都带命名空间：输入 `/nomo-cc:` 就会列出全部。OpenCode 的命令名是扁平且全局的，所以在那里 Nomo 的命令完全不带前缀。
</Tip>

它们都不会大声报错。即使无事可做也会干净地退出——`Not paired` 是成功，不是错误。

## pair {#pair}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:pair          # QR code, opens your browser
/nomo-cc:pair code     # one-time code, printed in the terminal
```

```bash Codex icon="/images/codex.svg"
$nomo-pair             # QR code, opens your browser
$nomo-pair code        # one-time code, printed in the terminal
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-pair             # QR code, opens your browser
/nomo-pair code        # one-time code, printed in the terminal
```
</CodeGroup>

不带参数时，它会在浏览器里打开一个配了主题的页面，上面有二维码。在 App 里扫一下，页面会自己翻成 **Paired ✓**。

`code` 参数完全跳过浏览器，直接打印一段可以手输的一次性配对码，供无头机器或 SSH 会话使用。它是刻意排在第二位的：那段配对码会落进你的终端，也就落进了智能体的转录记录。

配对若 **10 分钟**内未使用就会过期。一次配对覆盖的是这台机器，而不是某个智能体——同一台 Mac 上的 Claude Code、Codex 和 OpenCode 共用它。完整流程见[配对](/zh-Hans/setup/pairing)。

## status {#status}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:status
```

```bash Codex icon="/images/codex.svg"
$nomo-status
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-status
```
</CodeGroup>

一旦哪里看着不对，先运行它。一台健康的机器只有寥寥几行平静的输出——这里没有对勾，因为一切正常本身就是无话可说：

```
Nomo 2.1.17 · Claude Code

Phone         paired · https://api.nomo.gg · pairing 3e65a0cb…
Delivery      last event sent 11h ago · watchdog running (pid 25780)
Approvals     on — permission prompts are held and sent to your phone

Claude Code — you are here
  Hooks       firing · last 8s ago
  Sessions    1 of 4 tracked here
```

最上面三行描述的是**这台电脑**，无论你从哪个智能体运行，它们都一样。再往下才是你当前所在的那个智能体，用 `— you are here` 标出来。

<ResponseField name="Phone">
  这台电脑到底有没有配对，以及它连的 worker 和它持有的配对。`NOT PAIRED` 表示这里的任何东西都到不了 App，下面那个箭头会按你所在智能体的写法打印出 [pair](#pair) 命令。
</ResponseField>

<ResponseField name="Delivery">
  上一次真正有事件离开这台电脑是什么时候，以及看门狗在不在。看门狗没跑本身没关系——下一个会话开始时它会自己起来。但确实有会话在跑却显示 `never`，那就不对了。
</ResponseField>

<ResponseField name="Approvals">
  `on` 表示权限请求会被拦在这里并发到你手机。`PAUSED` 表示不会——它们直接进终端，而且会一直这样，直到有人恢复它，哪怕是几个月以后。如果你的手机不再问你任何事，这一行就是全部答案：见[暂停远程审批](/zh-Hans/sessions/approvals#pausing-it)。
</ResponseField>

<ResponseField name="Hooks">
  你的智能体有没有在给 Nomo 喂数据，以及上一次是多久以前。OpenCode 没有 hook，所以那里这一行叫 `Plugin`。什么都没触发？重启 Claude Code 让它的 hook 加载；Codex 那边运行 `/hooks`；OpenCode 那边重启它，好让插件加载。
</ResponseField>

<ResponseField name="Sessions">
  现在是按智能体分别计数的：`1 of 4 tracked here` 表示这台电脑正在跟踪四个会话，其中一个是你的。那些本该消失却还在的行，正是 [reset](#reset) 要处理的。
</ResponseField>

有问题时只会多出两个记号，别的什么都没有：`!` 是问题本身，`→` 是该怎么办，并且按你所在智能体的命令写法给出。这台电脑上其他每个智能体各占一行浓缩信息，放在 **Also on this computer** 下面——而当出问题的是*那些*智能体之一时，它也会在这里直接说出来，不必等你自己过去看：

```
Nomo 2.1.17 · Claude Code

Phone         NOT PAIRED — nothing from this computer reaches the app
              → run /nomo-cc:pair

Claude Code — you are here
  Hooks       firing · last 6s ago
  Sessions    1 of 3 tracked here

Also on this computer
  Codex       firing · last 12h ago · 2 of 3 tracked here
              ! Also runs the Claude Code plugin's hooks on every Codex event — double the work, no benefit.
              → in Codex run /hooks and untrust the `nomo-cc@nomo` entries
              → full detail: run $nomo-status inside Codex
  OpenCode    installed · no activity yet
```

无话可说的行会被略去——一台没配对的电脑，没有什么投递和审批可报。别的智能体的问题会在这里完整写出来，剩下的细节再指向那个智能体自己的状态命令。第一行还带着插件版本：反馈问题时请把它一并贴上。

## approvals {#approvals}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:approvals off      # pause on this computer
/nomo-cc:approvals on       # resume
/nomo-cc:approvals status   # which way is it set
```

```bash Codex icon="/images/codex.svg"
$nomo-approvals off         # pause on this computer
$nomo-approvals on          # resume
$nomo-approvals status      # which way is it set
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-approvals off         # pause on this computer
/nomo-approvals on          # resume
/nomo-approvals status      # which way is it set
```
</CodeGroup>

暂停**这台电脑**的远程审批，让权限请求直接进终端，而不是等你的手机。这是手机没电或不在手边时的应急出口。

```
Remote approvals are OFF for this computer — Claude Code permission prompts
will appear in the terminal as usual (your phone is not asked).
```

一台电脑一个开关，**所有智能体共用**——在 Codex 里暂停，同一台机器上的 Claude Code 和 OpenCode 也一起暂停。它不会解除任何配对，也不会碰你手机上的设置。

另外还有一个覆盖整部手机的开关：[设置](/zh-Hans/sessions/settings#remote-approvals)里的**在 iPhone 上回答**。

## reset {#reset}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:reset
```

```bash Codex icon="/images/codex.svg"
$nomo-reset
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-reset
```
</CodeGroup>

停掉看门狗，清理掉失效或残留的会话行，然后通知你的手机把它们丢掉。

```
Stopped the watchdog (it restarts automatically on your next session).
Cleared 4 stale session record(s) (4 end signals delivered to your phone).
Left 2 live sessions untouched.
Pairing and keys were not touched — use the unpair command if you want that.
```

会话行看着陈旧或重复时，这是最稳妥的一招，因为它会告诉你自己没动过什么。OpenCode 的会话行属于 OpenCode 的**服务器**，所以要是有一行清不掉，先退出 OpenCode——见[搭配 OpenCode 使用](/zh-Hans/sessions/opencode#reset-needs-opencode-closed)。

## unpair {#unpair}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:unpair
```

```bash Codex icon="/images/codex.svg"
$nomo-unpair
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-unpair
```
</CodeGroup>

撤销配对，并抹掉那台电脑上的密钥。

**在手机上**移除一台电脑不是一回事：那只会让它不再出现在你的 App 里，Mac 上的本地状态会一直留着，直到你在那边运行这条命令。

## 状态文件的位置 {#where-state-lives}

插件保存的一切都在 `~/.config/cc-status/` 里——配对信息、加密密钥（权限 `0600`）、每个被追踪会话一个文件，以及一份本地跟踪日志。这个文件夹里的东西不会发往任何地方。

## 源代码 {#read-the-source}
