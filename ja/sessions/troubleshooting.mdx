いまは、このページの仕事のほとんどをステータスのコマンドが代わりにやってくれます。コンピュータ全体を読み取り、おかしいところを平易な言葉で名指しし、それを直すコマンドを出力します。まずはこれを実行してください。

ここに残っているのは地図です。あなたが抱えてきた症状と、それに答える行、そしてステータスにはどうしても見えない数少ないものをまとめます。

## まずはステータス確認 {#start-with-status}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:status
```

```bash Codex icon="/images/codex.svg"
$nomo-status
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-status
```
</CodeGroup>

報告の対象は、あなたのセッションだけでなく**コンピュータ**全体です。ペアリング、配信、ローカルネットワークによる直接接続、承認、そのあとにいま使っているエージェントと、見つかったほかのすべてのエージェントが続きます。`!` は実際の問題で、その下の `→` がその対処です。実行したエージェントのコマンドの書き方に合わせて書かれます。たいていの場合、ここで終わります。

各行が何を意味するのかは、正常なマシンと壊れたマシンの出力を並べて[コマンド](/ja/sessions/commands#status)にまとめてあります。

<Note>
  ステータスのコマンドがネットワーク通信をすることはありません。わかるのは、このコンピュータが最後にイベントを送ったのがいつかということだけです — iPhone がそれを受け取ったかどうかも、中継サーバーや Wi-Fi の調子が悪いかどうかもわかりません。
</Note>

## 症状に対応する行 {#which-row-answers-it}

<AccordionGroup>

<Accordion title="このコンピュータから iPhone に何も届かない" icon="laptop">
  **Phone** を見てください。`NOT PAIRED` ならそれが答えのすべてで、その下の矢印にペアリングのコマンドが出力されます — 手順は[ペアリング](/ja/setup/pairing)にあります。

  ペアリング済みなのに何も届かない場合は、**Delivery** へ進んでください。
</Accordion>

<Accordion title="iPhone にセッションはあるのに、更新が止まった" icon="wifi">
  **Delivery** は、このコンピュータが最後に何かを送れたのがいつかを示します。それが最近なら、沈黙しているのは iPhone 側です。Nomo アプリを開くと更新が強制され、古いカードはただちに修正されます。

  色が抜けて `接続切れ？` と表示されているカードは、10 分間まったく何も聞こえていないという意味です。Mac のスリープ、ネットワークからの切断、ターミナルを閉じた場合も、iPhone からはすべて同じに見えます。

  セッションが実際に動いているのに Delivery が古いままか `never` の場合は、次に **Hooks** を見てください。
</Accordion>

<Accordion title="ローカルネットワークの直接接続がつながらない" icon="bolt">
  **LAN** を見てください。真ん中の行 — iPhone が最後にこの Mac へ到達した時刻 — が、直接接続が機能したことを示す唯一の証拠です。その前後の行は、このコンピュータが待ち受けているかどうかと、最後にアドレスを広告した時刻を示します。

  広告は最近なのに一度も到達がない場合、iPhone からここへの経路がありません。両方が同じネットワークにあること、[設定](/ja/sessions/settings#local-network)で「ローカルネットワーク」がオンになっていること、そして Nomo に iPhone のローカルネットワークの権限があることを確認してください。一度も広告されていない場合は、アドレスを運ぶセッションがまだないということです。`LAN` の行そのものがない場合、このコンピュータは一度も待ち受けていません。
</Accordion>

<Accordion title="iPhone が承認を求めてこない" icon="hand">
  **Approvals** を見てください。`PAUSED` は、そのコンピュータで一時停止のコマンドが実行されたという意味です — 何か月も前かもしれません。だからこそ、これまでは気づきようがありませんでした。そのマシンのセッションから再開すれば、許可リクエストは戻ってきます — [approvals](/ja/sessions/commands#approvals)。

  `on` と出ているなら、オフになっているスイッチは iPhone 側にあります。「iPhoneで回答」は初期状態でオフです — [設定](/ja/sessions/settings#remote-approvals)。見分け方は色です。挙がった手がすべて黄色（`要対応`、ターミナルでしか受け取れないもの）で、紫（`許可が必要`、回答できるほう）が 1 つもない、というのがその印です。[iPhone からの回答](/ja/sessions/approvals)をご覧ください。
</Accordion>

<Accordion title="セッションを開始したのに表示されない" icon="play">
  **Hooks** — フックのない OpenCode では **Plugin** です。これが発火していないなら、エージェントは Nomo に何も渡していません。この配線を読み込むのは、どのエージェントでも起動時だけです。Claude Code は再起動してください。Codex では `/hooks` を実行します。OpenCode も再起動してください。

  Codex はフックを明示的に信頼する必要があり、プラグインの更新があるとその確認が再び開きます。更新後に `/hooks` を実行するのが、そちらでのいつもの答えです — [理由](/ja/sessions/codex#hooks-have-to-be-trusted)。
</Accordion>

<Accordion title="OpenCode だけ何も表示されない" icon="rotate">
  **Plugin** の行が installed なのに活動がないと出ている場合、たいていはプラグインが入ったときに OpenCode がすでに起動していたということです。OpenCode がプラグインを読み込むのはサーバーの起動時の 1 回だけなので、終了してもう一度起動すればそれだけで直ります — TUI の再読み込みでは足りません。[reset に OpenCode を閉じる必要がある](/ja/sessions/opencode#reset-needs-opencode-closed)のと同じ理由です。
</Accordion>

<Accordion title="行が古いままか重複している" icon="broom">
  **Sessions** は、このコンピュータがまだ生きていると考えている数を数えています。実際より多いなら、ペアリングを解除せずに無効な行を消去してください。

  <CodeGroup>
  ```bash Claude Code icon="/images/claude-code.svg"
  /nomo-cc:reset
  ```

  ```bash Codex icon="/images/codex.svg"
  $nomo-reset
  ```

  ```bash OpenCode icon="/images/opencode.svg"
  /nomo-reset
  ```
  </CodeGroup>

  実行中のセッション、ペアリング、鍵はそのまま残ります —
  [出力の内容](/ja/sessions/commands#reset)。OpenCode の行は OpenCode のサーバーに属するため、
  消えない行があるときは先に OpenCode を終了してください。
</Accordion>

</AccordionGroup>

## ステータスには見えないもの {#what-status-cant-see}

以下の 3 つでは、Mac は仕事をきちんとこなしています。答えは iPhone 側にあります。

<AccordionGroup>

<Accordion title="Dynamic Island に何も表示されない" icon="circle-dot">
  ほとんどの場合、これは意図した動作です。セッションの表示は**オプトイン**です。コンピュータを開いてセッションを見つけ、スイッチをオンにしてください。あるいは[設定](/ja/sessions/settings#dynamic-island)で「新規セッションを自動追加」をオンにします。

  スイッチがオンなのに何も表示されない場合は、iOS の設定で Nomo の「ライブアクティビティ」が有効になっているか確認してください。次に、ほかのセッションが Dynamic Island を占有していないかを確認します。iPhone に表示されるのは[同時に 1 件](/ja/sessions/island#which-session-it-picks)だけで、あなたを待っているセッションは作業中のセッションより優先されます。
</Accordion>

<Accordion title="セッションのスイッチがオンのままグレー表示で、オフにできない" icon="toggle-off">
  そのセッションは許可を求めています。許可リクエストは、スイッチがどちら向きでも Dynamic Island に届きます — そうでなければ、iPhone をポケットに入れている間に届いた許可リクエストには回答できなくなり、この機能の意味そのものが失われるからです。そのため、応答待ちの間はスイッチが**オン**と表示されます。実際にそうなっているからです。

  **オフにできない理由。**オフにしても何も起きないからです。許可リクエストはいずれにせよ Dynamic Island に表示され続け — それがあなたに届く唯一の方法です — スイッチは指を離した 1 秒後にオンへ戻ってしまいます。言うことを聞かない操作を用意するくらいならと、Nomo は再びあなたに従えるようになるまでスイッチを固定します。

  あなたが選んだ設定が上書きされたわけではありません。許可リクエストに回答すれば、スイッチは元のオフへ戻ります — 誰も回答しなくても、1 時間以内に戻ります。そこからはまた自由に設定できます。
</Accordion>

<Accordion title="押さえたままにしたときのメニューに選択肢が足りない" icon="ellipsis">
  「Bashを常に許可（このセッション）」「メモを付けて拒否…」「回答…」は、いずれもプラグイン **2.0.0** が必要です。iPhone からの回答は 2.0 で追加された機能です。Nomo は、何も起きないボタンを出すのではなく、Mac が実行を保証できない選択肢を隠します。プラグインのバージョンはステータスの 1 行目に出力されるので、そこで確認してください。

  ドロワー上部の `プラグインの更新があります` というバナーは、まさにそれを示しています。インストールしたときと同じコマンドで更新してください。
</Accordion>

</AccordionGroup>

## ペアリングと復号 {#pairing-and-decryption}

iPhone が、読み取れない更新や、鍵を持っていないコンピュータの更新を受け取っている状態です。3 つとも、対処は同じ「そのコンピュータをもう一度ペアリングする」に行き着きます。

<AccordionGroup>

<Accordion title="行に「暗号化されたセッション」や「再接続中…」と表示される" icon="lock">
  iPhone は更新を受け取っていますが、まだ復号できていません。Nomo は数秒ごとに再試行し、通常は 1 回のポーリングで解消します。

  それでも続く場合、iPhone はそのコンピュータの正しい鍵をもう持っていません。Mac が再ペアリングされたか、ペアリングが置き換えられています。もう一度ペアリングしてください。
</Accordion>

<Accordion title="行に「取得できません」と表示される" icon="ban">
  同じことが 10 分間続いた状態です。生きているように見えて実はそうでない行を残すのではなく、Nomo はその行を無効と見なし、中身の推測をやめます。この行が Dynamic Island を占有することも、アクティブとして数えられることもありません。コンピュータを再ペアリングすれば元に戻ります。
</Accordion>

<Accordion title="コンピュータに「ペアリング解除済み」と表示される" icon="laptop">
  そのペアリングは取り消されています — Mac を再ペアリングしたか、そのマシンで [`/nomo-cc:unpair`](/ja/sessions/commands#unpair) を実行したかです。Nomo は失敗が続くのを見届けてからそう判断するので、Wi-Fi が一瞬不安定になっただけでこうなることはありません。

  「削除」をタップするか、そのままにしておいてください — 1 分ほどで自動的に消えます。また使いたくなったら、コンピュータをもう一度ペアリングします。
</Accordion>

</AccordionGroup>

## それでも直らないときは {#still-wrong-send-it-over}

[設定](/ja/sessions/settings#debug)で「セッション診断」をオンにし、問題のあるセッションを展開してください。その下に Nomo 内部の状態が 1 行、次のような形で表示されます。

```
2.0.0 · lan:hold 0.4s · dp
```

内容を解読しようとしなくて構いません — それは私たちの仕事です。その行のスクリーンショットを、期待していた動作と実際に起きたことを添えて送ってください。

<CardGroup cols={2}>
  <Card title="issue を立てる" href="https://github.com/KarrixLee/nomo/issues" icon="github">
    再現できるものはこちらが最適です。公開の場なので、非公開の情報は含めないでください。
  </Card>
  <Card title="メール" href="mailto:karrixlee1231@gmail.com" icon="envelope">
    アプリの「設定」＞「連絡先」からも送れます。
  </Card>
</CardGroup>

対象のコンピュータで実行した [`/nomo-cc:status`](/ja/sessions/commands#status) の出力もあると助かります — 1 行目のバージョンだけで、診断の半分は済みます。

## 機能リクエスト {#nothings-broken--you-just-want-something}

「なぜこれを iPhone からできないのか」は、不具合ではなく正当な疑問であることがよくあります。その一部はエージェントがプラグインに渡すものの実際の制約で、それは文書になっています。Codex 側は [Codex での利用](/ja/sessions/codex)に、OpenCode 側は [OpenCode での利用](/ja/sessions/opencode)に、ライブアクティビティに載せられるもの・載せられないものは [iPhone からの回答](/ja/sessions/approvals)にまとめてあります。

残りは、単にまだ作られていないだけです。
