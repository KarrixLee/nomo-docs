status 指令現在已經替這一頁做掉大部分的工作。它會讀過整台電腦，用白話指出任何不對勁的地方，並印出可以修好它的指令。請先執行它。

這裡剩下的是一張對照表：你帶著來的症狀、回答它的那一列，以及 status 真的看不到的那幾件事。

## 先從 status 開始 {#start-with-status}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:status
```

```bash Codex icon="/images/codex.svg"
$nomo-status
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-status
```
</CodeGroup>

它回報的是整台**電腦**，不只是你的 session：配對、傳送、批准，接著是你所在的那個代理，以及它找到的其他每一個代理。`!` 表示真的有問題，底下的 `→` 就是該怎麼處理，並以你發問時所在代理的指令寫法寫出來。大多數人看到這裡就結束了。

每一列各是什麼意思，以及一台健康的機器和一台壞掉的機器並排長什麼樣，都在[指令](/zh-Hant/sessions/commands#status)。

<Note>
  status 從不發出網路請求。它能告訴你這台電腦上一次送出事件是什麼時候 — 但不能告訴你你的手機有沒有收到，也不能告訴你中繼伺服器或你的 Wi-Fi 今天是不是狀況不好。
</Note>

## 對症看哪一列 {#which-row-answers-it}

<AccordionGroup>

<Accordion title="這台電腦送出的東西完全到不了我的手機" icon="laptop">
  看 **Phone**。`NOT PAIRED` 就是全部的答案，底下那個箭頭會印出配對指令 — [配對](/zh-Hant/setup/pairing)有完整流程。

  已經配對了卻還是什麼都沒有？請接著看 **Delivery**。
</Accordion>

<Accordion title="某個 session 在手機上，但停止更新了" icon="wifi">
  **Delivery** 說的是這台電腦上一次成功送出任何東西是什麼時候。如果那是不久前的事，沉默就出在手機那一側 — 打開 Nomo App，它會強制重新整理，過時的卡片會立刻自我修正。

  一張褪去顏色、寫著 `已斷線？` 的卡片，代表整整十分鐘什麼消息都沒聽到。Mac 睡著、離開網路，或終端機被關掉，從手機看起來都一模一樣。

  如果在真的有 session 在跑時，Delivery 很舊或顯示 `never`，請接著看 **Hooks**。
</Accordion>

<Accordion title="我的手機從來不問我要不要批准" icon="hand">
  看 **Approvals**。`PAUSED` 表示有人在這台電腦上執行過暫停指令 — 可能是好幾個月前的事，而這正是它以前根本沒人找得到的原因。在那台機器上的 session 裡恢復它，請求就會回來：[approvals](/zh-Hant/sessions/commands#approvals)。

  如果它顯示 `on`，那關著的開關是在你的手機上。「在 iPhone 上回答」預設就是關的 — 請看[設定](/zh-Hant/sessions/settings#remote-approvals)。判斷方式是顏色：每一隻舉起的手都是黃色（`需要協助`，那種只有終端機能處理），沒有一隻是紫色（`需要權限`，可以回覆的那一種）。請看[在手機上回覆](/zh-Hant/sessions/approvals)。
</Accordion>

<Accordion title="我開了一個 session，它卻從來沒出現" icon="play">
  看 **Hooks** — 在 OpenCode 裡則是 **Plugin**，因為它沒有 hooks。如果它沒在觸發，你的代理就沒有把任何東西交給 Nomo，而每個代理都只在啟動時載入那套接線：重新啟動 Claude Code、在 Codex 裡執行 `/hooks`、重新啟動 OpenCode。

  Codex 的 hooks 必須被明確信任，而一次外掛程式更新會重新開啟那道審核，所以在 Codex 那邊，更新後執行 `/hooks` 通常就是答案 — [為什麼](/zh-Hant/sessions/codex#hooks-have-to-be-trusted)。
</Accordion>

<Accordion title="偏偏只有 OpenCode 什麼都不顯示" icon="rotate">
  一列 **Plugin** 寫著已安裝卻沒有任何活動，通常表示外掛程式送達時 OpenCode 已經在跑了。OpenCode 只在伺服器啟動時載入一次外掛程式，所以把它結束再重新開起來就是全部的解法 — 只重新載入 TUI 是不夠的。這和[重設前要先關閉 OpenCode](/zh-Hant/sessions/opencode#reset-needs-opencode-closed) 是同一個原因。
</Accordion>

<Accordion title="各列看起來過時或重複" icon="broom">
  **Sessions** 算的是這台電腦仍然認為還活著的數量。如果那比你實際有的還多，清掉失效的那些，而不解除配對：

  <CodeGroup>
  ```bash Claude Code icon="/images/claude-code.svg"
  /nomo-cc:reset
  ```

  ```bash Codex icon="/images/codex.svg"
  $nomo-reset
  ```

  ```bash OpenCode icon="/images/opencode.svg"
  /nomo-reset
  ```
  </CodeGroup>

  進行中的 sessions、你的配對和金鑰都不會被動到 — [它會印出什麼](/zh-Hant/sessions/commands#reset)。OpenCode 的列屬於 OpenCode 的伺服器，所以有一列清不掉時，請先結束 OpenCode。
</Accordion>

</AccordionGroup>

## status 看不到的部分 {#what-status-cant-see}

以下三件事，你的 Mac 都把它該做的做好了。答案在手機上。

<AccordionGroup>

<Accordion title="動態島上什麼都沒出現" icon="circle-dot">
  幾乎一定是預期中的行為：sessions 是**你選了才會上去**的。打開那台電腦，找到那個 session，把它的開關打開 — 或是到[設定](/zh-Hant/sessions/settings#dynamic-island)開啟「自動加入新 sessions」。

  如果開關是開的卻還是什麼都沒有，請確認 iOS 設定裡 Nomo 的「即時動態」已啟用。接著確認不是另一個 session 佔著動態島：你的手機[一次只顯示一個](/zh-Hant/sessions/island#which-session-it-picks)，而正在等你的 session 排在工作中的前面。
</Accordion>

<Accordion title="某個 session 的動態島開關是開的、變灰，而且關不掉" icon="toggle-off">
  那個 session 正在請求權限。不管它的開關怎麼設，權限請求都會到達你的動態島 — 否則一個在你手機躺在口袋裡時抵達的請求，就會是一個你無法回覆的請求，而那正是這項功能的全部意義。所以在請求等待期間，開關會顯示為**開啟**，因為那才是實際正在發生的事。

  **為什麼你關不掉：**關掉它不會有任何作用。那個請求無論如何都會留在動態島上 — 那是它唯一能觸及你的方式 — 所以開關一秒後就會在你的拇指底下自己彈回開啟。與其給你一個不理你的控制項，Nomo 選擇按住它不動，直到它能重新聽你的為止。

  你選的東西沒有被覆寫。回覆那個請求，開關就會直接回到關閉、也就是你留下它的地方 — 或者如果沒有人回覆，一小時之內也會回去。然後它又是你的了。
</Accordion>

<Accordion title="按住後的選單少了幾個選項" icon="ellipsis">
  「一律允許」、「拒絕並附註…」和「回答…」都需要外掛程式 **2.0.0** — 在手機上回覆正是 2.0 加入的東西。Nomo 會隱藏 Mac 無法兌現的選項，而不是提供一個按了不會有作用的按鈕。status 會在第一行印出外掛程式版本，所以要確認就看那裡。

  面板頂端的「外掛程式有可用更新」橫幅，講的就是這件事。用你當初安裝的同一個指令更新。
</Accordion>

</AccordionGroup>

## 配對與解密 {#pairing-and-decryption}

你的手機收到了它讀不了的更新，或是一台它已經沒有金鑰的電腦。這三種情況的解法都一樣：重新配對那台電腦。

<AccordionGroup>

<Accordion title="某一列顯示「加密的 session」或「重新連線中…」" icon="lock">
  你的手機收到了那則更新，但還沒解開它。Nomo 每隔幾秒重試一次，通常在一次輪詢之內就會自行排除。

  如果一直持續，那就是你的手機不再持有那台電腦的正確金鑰 — 那台 Mac 被重新配對過，或是配對被取代了。請重新配對它。
</Accordion>

<Accordion title="某一列顯示「無法取得」" icon="ban">
  同一件事，只是失敗了十分鐘。與其留下一列看起來還活著、其實不是的內容，Nomo 會把它標為失效，並停止猜測它的內容。它不會驅動動態島，也不會被算成進行中。重新配對那台電腦就會恢復。
</Accordion>

<Accordion title="某台電腦顯示「已解除配對」" icon="laptop">
  那組配對被撤銷了 — 你重新配對了那台 Mac，或是在它上面執行了 [`/nomo-cc:unpair`](/zh-Hant/sessions/commands#unpair)。Nomo 會等到連續失敗夠久才相信這件事，所以這絕不會是「Wi-Fi 抖了一分鐘」得出的判斷。

  點一下「移除」，或就放著不管 — 它大約一分鐘後會自行清除。想要它回來時，再配對那台電腦一次。
</Accordion>

</AccordionGroup>

## 回報問題 {#still-wrong-send-it-over}

到[設定](/zh-Hant/sessions/settings#debug)開啟「session 診斷」，然後展開那個出問題的 session。它底下會出現一行 Nomo 自己的內部狀態，長得像這樣：

```
2.0.0 · lan:hold 0.4s · dp
```

不用試著解讀它 — 那是我們的工作。把那一列截圖傳給我們，並附上你預期看到什麼、實際看到什麼：

<CardGroup cols={2}>
  <Card title="開一個 issue" href="https://github.com/KarrixLee/nomo/issues" icon="github">
    任何可重現的問題都最適合走這條路。這是公開的，所以請不要放進私密內容。
  </Card>
  <Card title="寄信" href="mailto:karrixlee1231@gmail.com" icon="envelope">
    App裡也有，在「設定」>「聯絡方式」底下。
  </Card>
</CardGroup>

附上受影響電腦上 [`/nomo-cc:status`](/zh-Hant/sessions/commands#status) 的輸出也很有幫助 — 它第一行的版本就已經是一半的診斷了。

## 功能建議 {#nothings-broken--you-just-want-something}

「為什麼我不能在手機上做 X？」往往是個合理的問題，而不是一個 bug。其中有些是代理交給外掛程式的東西真的有限，而那都寫下來了：[搭配 Codex 使用](/zh-Hant/sessions/codex)和[搭配 OpenCode 使用](/zh-Hant/sessions/opencode)講這兩個代理，[在手機上回覆](/zh-Hant/sessions/approvals)講一個即時動態能容納和不能容納什麼。

其餘的就只是還沒做而已。

## 重新來過 {#starting-over}

在受影響的電腦上執行 [`/nomo-cc:unpair`](/zh-Hant/sessions/commands#unpair) 會移除配對並清除它的金鑰。然後[重新配對它](/zh-Hant/setup/pairing)。

**從手機上**移除一台電腦不是同一件事：那只會讓那台電腦不再出現在你的App裡，Mac 上的本機狀態會一直保留，直到你在那裡執行那個指令。
