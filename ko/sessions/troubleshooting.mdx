이제 이 페이지가 할 일의 대부분은 status 명령이 대신해 줍니다. 컴퓨터 전체를 읽어
잘못된 것을 평이한 말로 짚어 주고, 그것을 고치는 명령까지 출력합니다. 먼저
실행하십시오.

여기 남은 것은 지도입니다. 어떤 증상으로 찾아왔는지, 그 답이 되는 줄은 무엇인지,
그리고 status가 정말로 볼 수 없는 몇 가지입니다.

## status 명령 먼저 실행하기 {#start-with-status}

<CodeGroup>
```bash Claude Code icon="/images/claude-code.svg"
/nomo-cc:status
```

```bash Codex icon="/images/codex.svg"
$nomo-status
```

```bash OpenCode icon="/images/opencode.svg"
/nomo-status
```
</CodeGroup>

이 명령은 지금 세션만이 아니라 **컴퓨터**를 보고합니다. 페어링, 전송, 승인, 그다음
지금 사용 중인 에이전트와 발견된 다른 모든 에이전트입니다. `!`는 실제 문제이고 그
아래 `→`는 그에 대한 대처이며, 명령을 실행한 에이전트의 문법으로 적힙니다. 대부분은
여기에서 끝납니다.

각 줄의 의미는 정상인 컴퓨터와 고장 난 컴퓨터의 출력을 나란히 놓고
[명령](/ko/sessions/commands#status)에 정리해 두었습니다.

<Note>
  status는 네트워크 요청을 하지 않습니다. 이 컴퓨터가 마지막으로 이벤트를 보낸
  시점은 알려 주지만, 휴대폰이 그것을 받았는지, 워커나 Wi-Fi에 문제가 있는지는 알 수
  없습니다.
</Note>

## 증상별로 읽을 줄 {#which-row-answers-it}

<AccordionGroup>

<Accordion title="이 컴퓨터에서 보낸 것이 휴대폰에 전혀 도착하지 않음" icon="laptop">
  **Phone**을 읽으십시오. `NOT PAIRED`가 답의 전부이며, 그 아래 화살표가 페어링
  명령을 출력합니다 — [페어링](/ko/setup/pairing)에 전체 과정이 있습니다.

  페어링되어 있는데도 아무것도 오지 않는다면 **Delivery**로 넘어가십시오.
</Accordion>

<Accordion title="휴대폰에 있는 세션이 갱신을 멈춤" icon="wifi">
  **Delivery**는 이 컴퓨터가 마지막으로 무언가를 보내는 데 성공한 시점을 알려 줍니다.
  그 시점이 최근이라면 조용한 쪽은 휴대폰입니다. Nomo 앱을 열면 새로고침이 강제되어
  오래된 카드는 곧바로 바로잡힙니다.

  색이 빠지고 `연결 끊김?`으로 바뀐 카드는 10분 동안 아무 소식도 듣지 못했다는
  뜻입니다. Mac이 잠들었거나, 네트워크를 벗어났거나, 터미널을 닫은 경우가 휴대폰에서는
  모두 똑같이 보입니다.

  세션이 분명히 실행 중인데 Delivery가 오래됐거나 `never`라면, 다음으로 **Hooks**를
  읽으십시오.
</Accordion>

<Accordion title="휴대폰이 승인을 전혀 물어보지 않음" icon="hand">
  **Approvals**를 읽으십시오. `PAUSED`는 이 컴퓨터에서 누군가 일시 중지 명령을
  실행했다는 뜻입니다. 몇 달 전일 수도 있고, 그래서 예전에는 이 사실을 알아차릴
  방법이 없었습니다. 해당 컴퓨터의 세션에서 다시 켜면 요청이 돌아옵니다 —
  [approvals](/ko/sessions/commands#approvals).

  `on`이라면 꺼져 있는 스위치는 휴대폰 쪽입니다. **iPhone에서 답변**은 기본값이
  꺼짐입니다 — [설정](/ko/sessions/settings#remote-approvals). 구분하는 방법은
  색입니다. 든 손이 전부 노란색(`도움 필요`, 터미널에서만 처리할 수 있는 것)이고
  보라색(`권한 필요`, 답할 수 있는 것)은 하나도 없습니다.
  [휴대폰에서 답변하기](/ko/sessions/approvals)를 참고하십시오.
</Accordion>

<Accordion title="세션을 시작했는데 나타나지 않음" icon="play">
  **Hooks** — OpenCode에는 Hook이 없으므로 그쪽에서는 **Plugin**입니다. 동작하지
  않는다면 에이전트가 Nomo에 아무것도 넘기지 않고 있는 것이고, 어느 에이전트든 그
  연결을 시작할 때 한 번만 로드합니다. Claude Code는 재시작하고, Codex에서는
  `/hooks`를 실행하고, OpenCode는 재시작하십시오.

  Codex는 Hook을 명시적으로 신뢰해야 하며 플러그인 업데이트는 그 검토를 다시 엽니다.
  그래서 Codex에서는 업데이트 뒤에 `/hooks`를 실행하는 것이 대개의 답입니다 —
  [이유](/ko/sessions/codex#hooks-have-to-be-trusted).
</Accordion>

<Accordion title="OpenCode에서만 아무것도 보이지 않음" icon="rotate">
  설치됨이라고 나오는데 활동이 없는 **Plugin** 줄은, 플러그인이 도착했을 때 OpenCode가
  이미 실행 중이었다는 뜻인 경우가 많습니다. OpenCode는 서버가 시작될 때 플러그인을
  한 번만 로드하므로, 종료했다가 다시 시작하는 것이 해결책의 전부입니다. TUI를 다시
  로드하는 것만으로는 부족합니다.
  [초기화하려면 OpenCode를 종료해야 하는 것](/ko/sessions/opencode#reset-needs-opencode-closed)과
  같은 이유입니다.
</Accordion>

<Accordion title="행이 오래됐거나 중복되어 보임" icon="broom">
  **Sessions**는 이 컴퓨터가 아직 살아 있다고 믿는 세션의 수입니다. 실제보다 많다면,
  페어링을 해제하지 않고 죽은 행만 정리하십시오.

  <CodeGroup>
  ```bash Claude Code icon="/images/claude-code.svg"
  /nomo-cc:reset
  ```

  ```bash Codex icon="/images/codex.svg"
  $nomo-reset
  ```

  ```bash OpenCode icon="/images/opencode.svg"
  /nomo-reset
  ```
  </CodeGroup>

  실행 중인 세션, 페어링, 키는 건드리지 않습니다 —
  [출력 내용](/ko/sessions/commands#reset). OpenCode 행은 OpenCode 서버에 속하므로,
  지워지지 않는 행이 있으면 OpenCode를 먼저 종료하십시오.
</Accordion>

</AccordionGroup>

## status가 볼 수 없는 것 {#what-status-cant-see}

아래 세 가지는 Mac이 제 할 일을 하고 있는 경우입니다. 답은 휴대폰에 있습니다.

<AccordionGroup>

<Accordion title="Dynamic Island에 아무것도 표시되지 않음" icon="circle-dot">
  거의 언제나 의도된 동작입니다. 세션은 **직접 켜야** 표시됩니다. 컴퓨터를 열고
  세션을 찾아 스위치를 켜거나,
  [설정](/ko/sessions/settings#dynamic-island)에서 **새 세션 자동 추가**를
  켜십시오.

  스위치가 켜져 있는데도 아무것도 나오지 않으면, iOS 설정에서 Nomo의 **실시간
  현황**이 허용되어 있는지 확인하십시오. 그다음에는 다른 세션이 Dynamic Island를
  차지하고 있지 않은지 확인하십시오. 휴대폰에는
  [한 번에 하나](/ko/sessions/island#which-session-it-picks)만 표시되며,
  사용자를 기다리고 있는 세션이 작업 중인 세션보다 앞섭니다.
</Accordion>

<Accordion title="세션의 Dynamic Island 스위치가 켜진 채 비활성화되어 꺼지지 않음" icon="toggle-off">
  그 세션이 권한을 요청하는 중입니다. 권한 요청은 스위치가 어느 쪽이든 Dynamic
  Island에 도달합니다. 그러지 않으면 휴대폰이 주머니에 있는 동안 도착한 요청은
  답할 수 없는 요청이 되고, 그것은 이 기능의 존재 이유를 무너뜨립니다. 그래서
  요청이 대기하는 동안 스위치는 실제로 일어나는 일 그대로 **켜짐**으로
  표시됩니다.

  **끌 수 없는 이유:** 꺼도 아무 일도 일어나지 않기 때문입니다. 요청은 어차피
  Dynamic Island에 남아 있고 — 그것만이 사용자에게 닿을 수 있는 경로입니다 —
  스위치는 잠시 뒤 손가락 아래에서 다시 켜질 것입니다. 사용자를 무시하는 컨트롤을
  내놓는 대신, Nomo는 다시 따를 수 있을 때까지 스위치를 고정해 둡니다.

  사용자가 선택한 내용이 덮어써진 것은 아닙니다. 요청에 답하면 스위치는 원래대로
  꺼짐으로 돌아갑니다. 아무도 답하지 않아도 한 시간 안에 돌아갑니다. 그 뒤로는
  다시 사용자가 정하면 됩니다.
</Accordion>

<Accordion title="길게 터치 메뉴에 일부 항목이 없음" icon="ellipsis">
  **항상 허용**, **메모와 함께 거부…**, **답변하기…** 세 가지는 모두 플러그인
  **2.0.0**이 필요합니다. 휴대폰에서 답변하는 기능이 2.0에서 추가되었기
  때문입니다. Nomo는 아무 일도 하지 않을 버튼을 내놓는 대신, Mac이 지킬 수 없는
  항목을 숨깁니다. status는 첫 줄에 플러그인 버전을 출력하니 거기에서 확인하면
  됩니다.

  드로어 위쪽의 `플러그인 업데이트 사용 가능` 배너가 바로 그 뜻입니다. 설치할 때
  쓴 것과 같은 명령으로 업데이트하십시오.
</Accordion>

</AccordionGroup>

## 페어링과 복호화 {#pairing-and-decryption}

휴대폰이 읽을 수 없는 업데이트를 받고 있거나, 더 이상 키를 갖고 있지 않은
컴퓨터입니다. 세 가지 모두 해결책은 같습니다. 그 컴퓨터를 다시 페어링하십시오.

<AccordionGroup>

<Accordion title="행에 암호화된 세션 또는 다시 연결 중…이 표시됨" icon="lock">
  휴대폰이 업데이트를 받았지만 아직 열지 못한 상태입니다. Nomo는 몇 초마다
  재시도하며, 보통 한 번의 조회 안에 스스로 해결됩니다.

  계속된다면 휴대폰이 그 컴퓨터에 맞는 키를 더 이상 갖고 있지 않은 것입니다. Mac을
  다시 페어링했거나 페어링이 교체된 경우입니다. 다시 페어링하십시오.
</Accordion>

<Accordion title="행에 확인 불가가 표시됨" icon="ban">
  같은 문제가 10분 동안 이어진 경우입니다. 살아 있는 것처럼 보이지만 실제로는
  아닌 행을 남겨 두는 대신, Nomo는 그 행을 죽은 것으로 표시하고 내용을 추측하기를
  멈춥니다. 이 행은 Dynamic Island를 차지하지 않고 활성으로 계산되지도 않습니다.
  컴퓨터를 다시 페어링하면 복구됩니다.
</Accordion>

<Accordion title="컴퓨터에 페어링 해제됨이 표시됨" icon="laptop">
  그 페어링이 취소된 것입니다. 그 Mac을 다시 페어링했거나, 그 Mac에서
  [`/nomo-cc:unpair`](/ko/sessions/commands#unpair)를 실행한 경우입니다. Nomo는
  실패가 충분히 이어진 뒤에야 이를 사실로 받아들이므로, Wi-Fi가 잠깐 불안정했다는
  이유로 이렇게 판단하는 일은 없습니다.

  **제거**를 탭하거나 그대로 두십시오. 1분쯤 뒤에 스스로 정리됩니다. 다시 쓰고
  싶을 때 그 컴퓨터를 페어링하면 됩니다.
</Accordion>

</AccordionGroup>

## 문제 제보하기 {#still-wrong-send-it-over}

[설정](/ko/sessions/settings#debug)에서 **세션 진단**을 켠 다음, 이상하게
동작하는 세션을 펼치십시오. 그 아래에 Nomo 내부 상태가 다음과 같이 한 줄
표시됩니다.

```
2.0.0 · lan:hold 0.4s · dp
```

해석하려 애쓰지 않으셔도 됩니다. 그것은 저희 몫입니다. 그 행을 스크린샷으로
찍어, 기대한 동작과 실제로 일어난 일과 함께 보내 주십시오.

    주십시오.

버전만으로도 진단의 절반은 끝납니다.

## 기능 요청 {#nothings-broken--you-just-want-something}

"이건 왜 휴대폰에서 못 하나요?"는 버그라기보다 타당한 질문일 때가 많습니다. 일부는
에이전트가 플러그인에 넘겨주는 범위의 실제 한계이며, 그 내용은 문서로 적혀
있습니다. Codex 쪽은 [Codex 사용하기](/ko/sessions/codex)가, OpenCode 쪽은
[OpenCode 사용하기](/ko/sessions/opencode)가, 실시간 현황이 담을 수 있는 것과
없는 것은 [휴대폰에서 답변하기](/ko/sessions/approvals)가 다룹니다.

나머지는 아직 만들지 않았을 뿐입니다.

## 처음부터 다시 시작하기 {#starting-over}

해당 컴퓨터에서
[`/nomo-cc:unpair`](/ko/sessions/commands#unpair)를 실행하면 페어링이 제거되고
키가 지워집니다. 그런 다음 [다시 페어링](/ko/setup/pairing)하십시오.

**휴대폰에서** 컴퓨터를 삭제하는 것은 다릅니다. 그렇게 하면 그 컴퓨터가 앱에
표시되지 않을 뿐이며, 그 명령을 컴퓨터에서 실행하기 전까지 Mac은 로컬 상태를 그대로
유지합니다.
